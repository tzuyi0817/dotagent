# 丟棄式 prototype

prototype 是**為了回答一個問題而寫、答完就丟的程式碼**。問題決定形狀，先把問題釐清再動手：

- **「這頁該長怎樣？」**：在既有頁面上做多個結構截然不同的版本，瀏覽器裡切換比較。見 [references/ui.md](references/ui.md)。
- **「這個狀態模型或邏輯對不對？」**：一個雙擊就能開的單檔 HTML，讓人按按鈕看狀態變化。見 [references/logic.md](references/logic.md)。

兩個分支產物完全不同，選錯整個 prototype 就白做。問題模糊時先問使用者；使用者不在時依附近的程式碼判斷（頁面或元件選 UI，composable、store 或後端模組選邏輯），並把這個假設寫在 prototype 最上方。

## 共通規則

1. **從第一行就是丟棄式，而且看得出來**。放在它要服務的模組或頁面旁邊讓脈絡明顯，但目錄或檔名含 `prototype`，路過的人一眼知道這不是正式碼。
2. **一道指令就能跑**。UI 分支用專案既有的 dev 指令開既有頁面；邏輯分支雙擊 HTML。不需要思考怎麼啟動。
3. **預設不落地**。狀態放記憶體。持久化是 prototype 要驗證的對象，不是它的依賴；問題真的牽涉資料庫時，用名字明寫「PROTOTYPE，可清除」的暫存 DB 或本機檔案。
4. **不打磨**。沒有測試、沒有超出可執行所需的錯誤處理、沒有抽象。目的是快點學到東西。
5. **把狀態露出來**。邏輯分支每次操作後印出完整相關狀態；UI 分支每次切換都看得到切到了哪個版本。
6. **答完要收尾**。把驗證過的決定併進真實程式碼；prototype 本身 commit 到 `prototype/<name>` 分支、不進 main，在 PR 描述或 commit message 留下結論（回答了什麼問題、答案是什麼）與該分支的指標。main 只留決定，不留實驗。

完成判準：問題寫在 prototype 最上方；使用者能以一道指令或雙擊啟動；問題得到答案後，決定已進真實程式碼、prototype 已在獨立分支、結論有處可查。
