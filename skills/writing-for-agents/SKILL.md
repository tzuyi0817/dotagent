# 給 agent 讀的文件

適用於 agent 會讀取的每一種文件：skill、rules、AGENTS.md / CLAUDE.md，以及被這些檔案指向的參考文件。目標是**可預測**：agent 每次都走同一套流程，而不是碰運氣。本檔是原則與檢查項，不是模板；寫完一份文件後逐節對照一次。

## 先決定放哪裡：兩種成本

每寫一行都在花其中一種：

- **常駐成本**：AGENTS.md 的每一行、每個 model-invoked skill 的 description，不論這一輪用不用得到，都佔 context 與注意力。只放 agent 每次都需要的東西。
- **記憶成本**：user-invoked skill、沒有被任何檔案指到的文件，靠人記得它存在才會被用。這是保留主導權的代價，花在需要人判斷的地方，不需要的地方就拿掉。

經由指標才載入的內容，用指標那一行的常駐成本，換掉本體的常駐成本。

## 指標怎麼寫

指標是指向另一份文件的那一行：skill 的 description、AGENTS.md 裡「X 時讀 Y」的一句、rules 的 `paths`。agent 會不會去讀，由指標的**措辭**決定，不是被指到的內容。

- 觸發詞放最前面，用 agent 會在對話中實際遇到的詞：檔案類型、動作、使用者會說的話。
- 一個情境一個觸發條件，同義詞只留一個。
- 內容本身已經交代的身分（「這是一份…規範」）不重複寫進指標。
- 必讀的內容觸發不穩定時，先磨指標；磨不好才把內容搬進常駐區。

## 階層與漸進式揭露

文件內容分兩類：**步驟**（依序執行）與**參考**（需要時查）。依 agent 多快需要它排成三階：

1. **檔內步驟**：主體，依序寫。
2. **檔內參考**：每個分支都會用到的規則與定義，放在對應步驟附近，而不是另開一區。
3. **揭露出去的參考**：只有部分分支會用到的，放到 `references/` 或獨立檔案，由指標指過去。

**漸進式揭露**就是把內容沿這三階往下推。它首先不是為了省 token，而是保護階層：檔內參考太多會把步驟埋掉，agent 有沒有照步驟走變成機率問題。判準是分支：每條路徑都需要的留在檔內，只有某些路徑需要的推出去。

同一概念的定義、規則、例外放在同一個標題下。這和重複不同：重複是同一個意思寫在兩處，四散是一個意思被拆碎在多處；重複的刪到剩一處，四散的收攏到同一標題下。

單檔以 200–400 行為上限，超過見「什麼時候拆檔」。

## 步驟要有完成判準

每個步驟結尾寫清楚「做到什麼才算完成」。兩個要求：

- **分得出做完沒**：「已理解需求」分不出，「每個變更檔案都能以 `git show` 讀到、每個 hunk 都對應到行號」分得出。界線模糊時 agent 會提早收工，注意力跑到下一步。先磨判準；真的磨不利、又觀察到趕工時，才把後續步驟拆到另一個 context，見下一節。
- **要求夠高**：「列出變更」與「每一個被改到的 model 都有交代」逼出的查證深度完全不同。參考型文件也能加這一道：「每條規則都套用過」。

## 什麼時候拆檔

拆成兩份會多花一種成本：多一份要指到的檔（常駐），或多一份要記得的檔（記憶）。只在這一刀划算時才拆：

- **依順序拆**：後面的步驟還看得到時，agent 會趕完眼前這一步。把後續步驟切到另一個 skill 或子代理，讓它看不到，眼前這步的查證會做得更足；同一個檔案裡是藏不住的。反過來也成立：把原本分開的步驟併進同一檔，每一步都暴露在後續步驟面前，是提早收工的常見來源。
- **依觸發方式拆**：見「skill 專屬」。
- 超過 200–400 行是拆的訊號，但拆法仍依分支或順序決定，不是對半切。

## 引導詞與正向表述

**引導詞**是模型預訓練裡已有的精簡概念，整份文件反覆用同一個詞指同一種行為，例如 review-pr 的 Finder、Verifier、「阻擋」，或本 repo 通用的「完成判準」。一個詞取代一句描述，agent 每次看到就伸手拿同一種行為；同一個詞出現在 prompt、文件、程式碼時，觸發也更穩。自創詞要先定義，優先用既有的詞。

同一組概念在三處各寫一遍、一個指標花一整句比畫一個意思，都是該收斂成一個詞的訊號。

禁令會把被禁的行為帶進 context，反而更容易被做出來。寫目標行為（「註解寫成一行」），而不是寫「不要寫多行註解」。只有無法正向表述的硬性護欄才用禁令，而且要配上正向目標。

## 修剪

- **單一事實來源**：一個意思只寫在一處，改行為只改一處。重複會把那個意思的權重灌高。
- **環境是事實來源**：`package.json` 的 scripts、設定檔、目錄結構、`--help` 自己會說話，文件重述它們只是會過期的快取。只記 agent 用看的看不出來的東西：不成文慣例、某個決定的理由、設定檔不會招認的陷阱。
- **相關性**：每一行問「還影響 agent 做這件事嗎」。從沒影響過的鋪陳、已過期的描述，整句刪。文件越短越容易維持相關；沒有修剪紀律，文件會層層沉積，直到沒人知道哪些還活著。
- **no-op**：模型預設就會做的指令，寫了等於沒寫，整句刪。判斷方法是跑一次看行為有沒有變，不是辯論。太弱的引導詞（agent 本來就夠仔細時寫「仔細」）也是 no-op，換更強的詞。

## skill 專屬

- **model-invoked**（不設 `disable-model-invocation`）：description 常駐，agent 能自行觸發，其他 skill 也能用 Skill tool 呼叫。手動輸入名稱照樣能觸發，description 只是多給 agent 一條路，不會拿走人的入口。只在 agent 必須自己找到它、或有別的 skill 要呼叫它時才選；description 寫成觸發條件。
- **user-invoked**（`disable-model-invocation: true`）：零常駐成本，只能由人輸入名稱觸發，沒有任何 skill 能呼叫它。會動手改東西、或需要人主導節奏的流程用這種；description 只留一行給人看的摘要，加 `argument-hint` 提示要接什麼。
- 兩個 user-invoked skill 共用的參考，誰也呼叫不了誰，放到 skill 之外的一般檔案（如 `rules/`）讓兩邊都指過去。
- 只在有獨立觸發詞、或有別的 skill 要呼叫時，才把一段拆成獨立的 model-invoked skill；多付的是一份常駐 description。
- user-invoked skill 多到記不住時，寫一個列出各 skill 與使用時機的路由 skill；它只能提示，不能替人觸發。
