這是撰寫任何 agent 會讀取的文件的參考：skill、`AGENTS.md` / `CLAUDE.md`、經由指標（pointer）才會讀到的文件。包裝不同，寫法相同：同一組槓桿讓每一種文件都可預測。所謂可預測，是 agent 每次執行都走同一套**流程**，而不是每次都產出同樣的結果。

寫的是 skill 時，另讀 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)：frontmatter、觸發方式的選擇、路由 skill。

## 脈絡指標（context pointer）

**脈絡指標**是放在 agent context 裡的一個參照：它指名某份不在 context 內的材料，並寫明去讀它的條件。skill 的 description 是一個脈絡指標；`AGENTS.md` 裡指名某份文件的一行也是同一種東西。決定 agent 何時去讀那份材料、讀得多可靠的，是指標的**措辭**，不是它指向的目標。必讀的材料卻配上措辭薄弱的指標，是一個變異性（variance）bug：先把措辭磨利，磨不利才把材料直接寫進來。

指標做兩件事：說明那份材料是什麼，以及列出該觸發讀取的**分支**（branch；分支是文件處理的一種獨立情況，不同次執行會走過文件的不同路徑）。常駐載入的指標每一個字都在每一輪付費，所以它比本文更需要狠修：

- **把引導詞放到最前面**：指標正是引導詞發揮觸發作用的地方。
- **一個分支一個觸發條件。** 同一個分支換個同義詞再寫一次，只是把一個分支寫了兩遍；合併它們，只留真正不同的分支。
- **本文已經交代的身分說明，刪掉。**

## 兩種負載

你新增的每一份文件、每一個指標，都在花兩種預算之一：

- **脈絡負載（context load）**是常駐材料對 agent context window 的成本：`AGENTS.md` 的一行、skill 的 description、任何每一輪都待在 context 裡的東西，不論有沒有被用到，都在消耗 token 與注意力。
- **認知負載（cognitive load）**是落在人身上的成本：有哪些文件、各自什麼時候該拿出來用。人就是那份索引。這不是一個要壓到最低的成本，而是人保有主導權的代價：把它花在需要人判斷的地方，不需要的地方就拿掉。

只經由指標才會讀到的材料，用指標那一行的代價換掉了脈絡負載；完全沒有指標的材料，則全靠認知負載撐著。

## 資訊階層

一份文件由兩種內容組成：**步驟**（step；agent 依序執行的動作）與**參考**（reference；定義、規則、需要時才查的事實）。兩者可以自由混搭：全是步驟（像食譜）、全是參考（審查的規則、這份 skill 本身）、或兩者皆有。核心的決定是每一段內容該落在**資訊階層**的哪一階；這是一把依「agent 多急著需要這段材料」排序的梯子：

1. **檔內步驟**是主階：agent 要做什麼、依什麼順序。
2. **檔內參考**是需要時才查的。常常是一組正當的扁平同儕（審查的每條規則都在同一階），這是合理的安排，不是壞味道。
3. **揭露出去的參考**被推到另一個檔案，經由脈絡指標才會讀到，指標觸發時才載入。範圍從同一資料夾裡的兄弟檔，到放在任何地方、任何文件都能指向的完全外部參考。

往下推得太少，頂層就臃腫；推得太多，就把 agent 真正需要的材料藏起來了。這股張力就是整個決定的所在。

**漸進式揭露**就是沿梯子往下移（移出主檔、放到指標後面），好讓頂層保持可讀。它首先不是為了省 token，而是保護階層的手段。分支是最乾淨的揭露判準：每個分支都需要的就寫在檔內，只有部分分支會用到的就推到指標後面。文件含有步驟時，該揭露卻留在檔內的參考會把步驟埋掉，agent 有沒有注意到步驟變成擲硬幣：這是一個影響變異性的槓桿，不只是可讀性。

**就近放置（co-location）**是檔內的配套：梯子決定一段內容放**多深**，就近放置決定它放定之後**旁邊是什麼**。一個概念的定義、規則、注意事項放在同一個標題底下，不要四散，讀到其中一部分就會順帶讀到鄰居。判準是：文件讀起來應該像一份為 agent 寫的說明文件。集中的材料讀起來是那樣，四散的材料不是。（這和重複不同：重複是同一個意思出現在兩處；四散是同一個意思被拆碎在多處。）

**蔓生（sprawl）**是這裡的失敗模式：文件就是太長，即使每一行都還活著、都不重複。注意力被多出來的篇幅稀釋，每多一行就多一行要維持其相關性。解法就是那把梯子：把參考揭露到指標後面，並依分支或順序切分，讓每條路徑只帶它需要的東西。

## 步驟與完成判準

每個步驟都以**完成判準**（completion criterion）收尾，也就是告訴 agent 這一步做完了的條件。兩個性質讓它成為槓桿：

- **清晰度**：agent 分得出做完與沒做完嗎？模糊的界線（「已達成理解」）會招來**過早完成**：步驟還沒真正做完就結束它，注意力滑向「做完了」這件事本身。眼前還看得到的後續步驟（**完成後步驟**）提供了那股拉力；判準的清晰度則是阻力。依序防守：**先把界線磨利**（局部、便宜）；只有在它怎麼磨都模糊、**而且**你確實觀察到趕工時，才用切分順序的方式把後面的步驟藏起來。藏只有跨越真正的 context 邊界才有效（交接或派出子代理；inline 呼叫會把後續步驟留在 context 裡，什麼都沒清掉）。
- **要求強度**（demand）：它要求多少。「每一個被修改的 model 都已交代」逼出徹底的工作，「產出一份變更清單」則不會。要求強度驅動**查證功夫**（legwork；agent 在工作裡做的挖掘，潛藏在措辭中，而非寫成獨立的步驟），而且它不受限於步驟：「每條規則都套用過」約束的是一整塊扁平參考，正如「每個步驟都做完」約束的是一段順序，這就是全參考型文件仍然能帶有一道窮盡門檻的方法。

最強的判準既可檢查、又窮盡。

## 什麼時候拆分

把一份文件拆成兩份會花掉兩種負載之一，所以只在這一刀划算時才拆：

- **依順序拆**：當完成後步驟誘使 agent 趕完眼前這一步時，就在這裡把一連串步驟切開。讓它們不在視線內，能逼出對當前任務更多的查證功夫。小心反向操作：合併順序會把每一步的後續步驟暴露給它，招來過早完成。
- **依觸發方式拆**，skill 限定：見 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引導詞（leading word）

**引導詞**是一個早已存在於模型預訓練中的精簡概念，agent 執行文件時用它來思考（_lesson_、_fog of war_、_tracer bullets_）。它以 token 的形式重複出現，從不展開成句子，於是累積出一個分散式的定義，用最少的 token 錨定一整片行為區域，靠的是召喚模型本來就有的先驗。自創新詞也行，前提是定義清楚，但生造的詞召喚不到任何先驗：預訓練詞免費給你的東西，你得用定義的 token 來買；先找既有的詞。

它錨定兩次。在本文裡錨定**執行**：這個詞每次出現，agent 都伸手去拿同一種行為；在扁平參考裡，它把注意力聚焦在某一類要找的東西上。在指標裡錨定**觸發**：當同一個詞同時活在你的 prompt、你的文件、你的程式碼裡，agent 會把這套共同語言和那份材料連起來，更可靠地讀到它。

主動找機會用引導詞重構。同一組三件事在三個地方各寫一遍、一個指標花一整句去比畫一個概念，這些段落都在求你把它們收斂成一個 token：

- 「快、確定性、低開銷」收斂成 _tight_（一個 _tight_ 的 loop）。
- 「一個你相信的 loop」收斂成 _red_，把模糊的關卡變成二元可觀察的狀態（loop 在這個 bug 上轉 _red_，或者沒有）。

你贏兩次：token 更少，agent 掛思考的鉤子更利。預設每一份文件都帶著可以用引導詞退役的重述。去找出來。

**否定**是這個槓桿旁邊的失敗模式：用禁令來引導，會把被禁止的行為拖進 context，讓它變得**更**容易被取用，而不是更少。_別想大象_，於是滿腦子只剩大象；否定只是一個弱修飾語，被強烈啟動的概念輾過去，禁令讀起來一半像是在叫你去做那件事。用**正向**的方式下指令：直接說出目標行為（「寫單行註解」），被禁的那個就永遠不必說出口。禁令只有在它是一道無法正向表述的硬性護欄時才配留下；即使如此，也要搭配正向目標，讓注意力落在該做的事情上。

## 修剪

- 每個意思只放在**單一事實來源**：一個權威位置，改行為就只改一處。**重複**（同一個意思出現在不只一處）花維護成本與 token，還會把那個意思在梯子上的顯著度灌到超出它真正的位階。（這是引導詞不小心的反面：引導詞刻意重複的是 token，從不是意思。）
- **環境**也是事實來源（`package.json` 的 scripts、設定檔、目錄結構、`--help` 的輸出），一份把它重述一遍的文件只是**快取**：一次查詢的副本，只有在查詢很貴時才值回它的負載。快取 agent 用看的找不到的東西：沒寫下來的慣例、某個選擇背後的理由、沒有任何設定檔會招認的陷阱。一個檔案、一道指令就查得到的，留給環境，它在那裡不會過期。
- 逐行檢查**相關性**：這一行還跟文件要做的事有關嗎？一行失去相關性，可能是從來就跟任務無關（純粹的鋪陳，或一個該被揭露出去的分支），也可能是它描述的行為或世界變了而過期。文件越短越容易維持相關。沒有修剪紀律，預設的下場就是**沉積**：因為加感覺安全、刪感覺危險而層層堆下的過期沉積，直到你得往下鑽探才找得到還活著的部分。
- 逐句獵殺 **no-op**：模型預設就會遵守的指令，花了負載卻什麼都沒說。判準（相對於預設行為，它有沒有改變行為？）是相對於模型的，不是相對於讀者的：兩個人對某句是不是 no-op 有分歧，分歧的其實是預設行為是什麼，用跑一次文件來裁決，不是用辯論。一句話沒過關，整句刪掉，不要只修剪幾個字。這個判準也用來給引導詞打分：弱到贏不過預設的詞（agent 本來就算徹底時還說 _be thorough_）就是 no-op，解法是更強的詞（_relentless_），不是換一種技巧。
