# 前端程式碼審查

## 用途
當使用者要求審查前端程式碼（尤其是 `.tsx`、`.ts`、`.vue` 或 `.js` 檔案）時使用此技能。支援兩種審查模式：

1. **待提交變更審查** — 檢查已暫存或工作區中待提交的檔案，在提交前標記出違反檢查清單的項目。
2. **指定檔案審查** — 審查使用者指定的特定檔案，並回報相關檢查清單的發現。

對每個適用的檔案與模式，皆須依照以下檢查清單執行。

## 檢查清單
請參閱 [references/code-quality.md](references/code-quality.md)、[references/performance.md](references/performance.md)、[references/business-logic.md](references/business-logic.md)，這些檔案依分類列出了完整的規則清單，視為必須遵守的規範依據。

針對每條規則的違規情況，標記緊急程度元資料，讓後續審查者能夠優先排序修復工作。

## 審查流程
1. 開啟相關的元件或模組，蒐集與 class 名稱、React Flow hooks、prop 記憶化及樣式相關的程式碼行。
2. 針對每條審查規則，記錄程式碼的偏差之處，並擷取具代表性的程式碼片段。
3. 依照下方模板撰寫審查報告。先依**緊急**標記分組，再依分類順序排列（程式碼品質、效能、業務邏輯）。

## 輸出格式要求
呼叫時，回應必須嚴格遵照以下兩種模板之一：

### 模板 A（有發現問題）
```
# 程式碼審查
發現 <N> 個緊急問題需要修復：

## 1 <問題的簡短說明>
FilePath: <路徑> 第 <行號> 行
<相關程式碼片段或說明>


### 建議修復方式
<建議修復方式的簡短說明>

---
... （每個緊急問題依此格式重複）...

發現 <M> 個改善建議：

## 1 <建議的簡短說明>
FilePath: <路徑> 第 <行號> 行
<相關程式碼片段或說明>


### 建議修復方式
<建議修復方式的簡短說明>

---

... （每個建議依此格式重複）...
```

若無緊急問題，省略該區塊。若無改善建議，省略該區塊。

若問題數量超過 10 個，摘要顯示為「10+ 個緊急問題」或「10+ 個改善建議」，並只輸出前 10 個問題。

不要壓縮區塊之間的空行，保持原樣以提高可讀性。

若使用模板 A（即有問題需修復），且至少有一個問題需要修改程式碼，請在結構化輸出後附上一個簡短的後續詢問，詢問使用者是否希望套用建議的修復方式。例如：「您希望我根據建議修復方式來處理這些問題嗎？」

### 模板 B（無問題）
```
## 程式碼審查
未發現任何問題。
```
