# 毫不留情地追問到對齊為止

目的是在動手前消除「做出來的不是我要的」。毫不留情地訪談使用者，把想法展開成一棵**決策樹**：每個決定底下掛著依賴它的下一層決定。只問，不做：在使用者確認對齊之前，不寫程式、不改檔案。沒有帶參數時，以目前對話裡已經討論的內容為對象。

## 回合

每一回合問出**前沿**：所有前提都已確定、現在就能問而不必猜答案的問題。整個前沿一次問完，每題編號並附上你建議的答案，然後等使用者回覆。用一般對話文字提問，不用 AskUserQuestion，讓使用者能用自己的話回答。

```
### Q1 <標題>
<問題，可含多段與選項>

**建議**：<你的答案與一句理由>

### Q2 <標題>
…
```

使用者回答後重新計算前沿：剛定下的決定會解開新的問題，也可能讓某些問題失效。一題的答案若取決於本回合另一題，留到下一回合再問。每題都追到能做決定的粒度：答案含糊、或帶出新的分支時，下一回合接著追，不替使用者補完。

## 分工

- **事實是你的事**：既有實作、套件行為、設定、檔案結構，自己查或派子代理查，不問使用者。查詢進行中時，只有依賴它的題目等結果，其餘照問。
- **決定是使用者的事**：取捨、範圍、優先順序，每一題都交給使用者，附建議但不代答。使用者可以用編號回答，或說「都照建議」。
- 使用者說「夠了」時停下，整理目前的共識，標明仍未決的分支。

## 完成判準

前沿為空：決策樹每個分支都走過，沒有任何事被默默假設。向使用者摘要共識並得到確認後才結束；之後怎麼進行（直接實作、`/plan`、寫 spec）由使用者決定。
